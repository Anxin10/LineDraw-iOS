# LineDraw iOS 1.1.0 build 14：直接換頁與減少重複查詢

使用者核准 2026/09/29 的定位與方案後實作。build 13 手機既有診斷顯示最近五筆佇列 42.79 秒、21 次完整畫面讀取共 8.91 秒，另有兩次 POST elements 的失效元素錯誤。一般模式當時沒有完整 OCR／換頁分段時間，不能把其餘耗時全部歸因於 OCR。

## 實作

1. `LocalWDA.open` 先送出下一個已解析網址，不在送出前讀舊結果、關閉優惠券或做頂部 OCR。點擊成功回應和參加紀錄保存仍先完成；不等待中獎結果，點擊回應不明仍進 REVIEW、不重送。
2. 開網址回應只代表指令被接受。新 `DeviceNavigationGuard` 要求完整畫面可觀測到優惠券已離開，或 WebView 暴露精確目標網址，才允許辨識新活動。僅文字變成中獎／已結束、畫面尺寸改變、稀疏查詢空白或空資料，都不算新頁。無法確認但優惠券仍可關閉時，執行一次原有關閉／確認流程，再開同一個目標網址。這是沒有送出抽選前的導覽復原；不是重送抽選。關閉失敗會停止。
3. 已確認換頁、底部原生 Button、唯一有效目標與優惠券標題齊全時，一次新觀察即可授權座標點擊。無法辨識的版面、非原生目標及 OCR 仍走穩定觀察；OCR 點擊前仍重讀。保留前景 App、對話框、尺寸／方向、座標邊界與取消檢查。
4. 原生觀察允許在 0.75 秒內跨過保存意圖的耗時，避免原 0.2 秒門檻頻繁觸發第三次畫面讀取。尺寸／方向變更、操作已發生、OCR 或逾齡都會重新取景。
5. 首次畫面尺寸在 WDA connect 階段初始化，避免第一次進入 LINE 時才呼叫 window/size；後續仍依新畫面的 App 範圍更新尺寸。
6. 頂部可同時存在上一輪失敗與目前執行中的 LineDraw 系統工作橫幅。僅使用 OCR 精確辨識到的自身標題，選擇最上方且範圍合法的標題左側收合；不因重複自身標題直接失敗，不點右側停止按鈕。遇到第三方通知遮擋，最多觀察 6 秒等待自行消失；逾時仍停止，不點通知。新增短暫遮擋、持續遮擋、取消與逾時讀取測試。
7. POST elements 出現可恢復的查詢錯誤，立即在本輪停用快速查詢；包含 stale element reference，不再每頁重試。原本依成功查詢成本切換的機制保留。
8. 一般執行新增每筆 `DEVICE_ITEM_TIMING`、整輪 `DEVICE_PHASE_TIMING` 和 `DEVICE_LOOKUP`。包含開網址、畫面觀察次數／耗時、點擊驗證與送出、保存、直接開頁與關閉退回次數。`handoff.ackToNextURL` 量測點擊回應到下一個開網址請求的間隔。階段互相包含，不能把 phase 與 HTTP 時間全部相加。
9. 背景工作進度依開網址、確認新頁、保存操作意圖、點擊回應、保存送出紀錄等實際完成步驟，以及成功的 WDA 唯讀回應更新。只靠整筆／階段里程碑，在頁面遲遲未穩定時仍可能超過系統容許的無進度時間；完成的畫面與狀態讀取也屬於實際工作。不以計時器、失敗請求或重複 UI 更新製造進度；總工作量依預估讀取數調整，始終保留最後清理工作。系統介面更新最多每 4 秒一次，只由已完成事件觸發，沒有額外 sleep、計時灌進度或延後下一筆指令。已抽選結果仍需兩次一致觀察，但不再因無關優惠券區塊移動而重置。

座標仍取自本機最新辨識的按鈕矩形中心，沒有跨手機固定 x/y。跨頁座標區域快取留待分段數據證明有收益再處理；本次先完成核准方案的前三項。

- Debug 簽署建置與 Release 未簽署建置通過。
- 第一次實機測試在 WDA 啟動階段約 36 秒回報背景工作結束，尚無抽選操作、尚未進入新的換頁流程。使用者確認無提示也未按取消。重新啟動後 WDA 成功；未把這次偶發中斷宣稱為已修復。
- build 14 較早修訂（加入最後進度／橫幅修正前）的本機 Safari 五筆生產佇列流程：5/5 通過，每筆只讀取一次畫面、每筆 acknowledgement 恰為 1。佇列 31.28 秒、含啟動 34.21 秒；四次點擊回應到下一個網址請求，合計 0.0564 秒（平均約 14 ms）。這個 fixture 使用記憶體紀錄及頁面專用識別，不代表 LINE 真實載入或磁碟保存的相同耗時。此前 build 12 fixture 為 52.09 秒，但非同條件 A/B，不宣稱提升比例。
- 首次 LINE 複查在第一筆開網址後 GET window/size 逾時，尚未操作抽選。已將初始化尺寸移至進入 LINE 前；後續各輪尺寸查詢約 0.13～0.24 秒，沒有再於該操作逾時。
- 後續 LINE 複查確認兩個 LineDraw 系統工作橫幅疊放，原來要求唯一標題而停止；已新增疊放標題選擇及測試，保留未辨識橫幅不操作的限制。
- 兩次一般唯讀複查在元素查詢逾時後失去 WDA 連線；另兩次分別用一般／完整讀取對照，成功辨識前兩筆 COMPLETE、ALREADY，但第三方通知遮擋第三筆而停止。後兩輪沒有背景工作取消；這些證據不能證明所有斷線都是快速查詢造成，也不能宣稱偶發斷線已根治。已補上通知自行消失的有界等待。
- 實機 syslog 明確記錄 `Task has not reported progress within expected cadence, marking stalled`，無更新時間約 30.87 秒，隨後觸發 expiration handler。這次證明是系統無進度判定，並非使用者取消。已將成功唯讀回應納入進度；單次請求本身超時／沒有成功回應時不灌進度，原逾時停止規則仍適用。
- 最終修訂的 LINE 唯讀複查 5/5 通過，結果依序 COMPLETE、ALREADY、ALREADY、COMPLETE、ALREADY；共 106.90 秒（包含 WDA 啟動與清理）。沒有抽選／加入好友／兌換點擊，僅在三筆無法直接確認新頁時關閉優惠券復原；一般模式最後依實測成本切換到完整讀取。此測試包含終態兩次觀察、慢畫面與換頁復原，不是五筆新抽選的速度量測，也不宣稱提升比例。
- 最終本機原生按鈕／單次 18 秒讀取逾時注入：5/5 通過，每筆 acknowledgement 恰為 1；佇列 73.66 秒、含啟動 76.40 秒。第一筆含逾時復原讀取兩次，其餘每筆只觀察一次，沒有關閉退回。四次點擊回應到下一網址請求合計 0.0601 秒（平均約 15 ms），沒有底部 OCR。這是受控 Safari fixture，不是 LINE 新券量測。
