# 抽選來源更新：1.1.0 build 17

## 問題與修正

2026/10/02 的 Funbox 頁面仍保留 `.draw-store`、`.draw-item` 與 `data-draw-id`／`data-draw-href`。真正造成解析失敗的是新竹巨城店的「BX-37 雙重極限衝擊戰鬥盤 豪華組（採取上架販售）」：它只有商品文字，沒有抽選 ID、連結或點擊標記。舊版要求每一列都有抽選連結，因此整份清單被拒絕。

現在略過沒有抽選連結及操作標記的純展示列。有 ID 卻缺網址、有點擊標記卻缺 ID、重複 ID、不允許的連結或完全沒有有效抽選列，仍會回報錯誤並保留前次資料。來源順序及既有列識別維持不變。

當次讀取的原站共有 76 間店、1,290 個商品展示列，修正後取得 1,289 筆抽選；陀螺獵人公開 API 回傳 1,287 筆。兩站各自維護資料，筆數不必相同。純販售商品不加入抽選佇列；時間未提供的活動保持「時間未確認」，不猜測開抽時間。

## iPhone 使用方式

1. 開啟「抽選」，右上角清單類型選「網站抽選」。
2. 點上方來源按鈕，選「Funbox 原站」或「陀螺獵人」。
3. App 同步所選網站，完成後才切換來源。之後下拉或按同步，都會沿用目前來源。
4. 切換成功後重新選擇篩選與活動；失敗或取消時，原來源、勾選與清單保留。

來源選擇及兩站的快取、同步時間各自保存，舊資料預設視為 Funbox，不重設本機紀錄。同一張已解析的 LINE 券共用完成紀錄；五連結測試、離線示範仍與正式網站紀錄分開。有效的陀螺獵人空清單會封存該來源舊活動，不清除另一來源與完成紀錄。

陀螺獵人使用 HTTPS `/api/funbox/data`，MySQL DATETIME 依 Asia/Taipei 解讀。短網址仍需解析為有效的 LINE 券網址才可執行。

## 接續與 Mac 相容性

手機自主模式的批次保存開始時來源與篩選，接續新增活動時不變更來源。同步、執行及暫停中的來源切換保持鎖定。

Mac 輔助模式也支援兩來源；需同步更新 `ios-wda` 並重新啟動。新版 App 會檢查 Mac 回報的來源能力，舊 Mac 版本會提示更新，不會把陀螺獵人任務默默接到 Funbox。API 不接受 HEAD 請求，故陀螺獵人的網路檢查使用 GET 並立即釋放回應。

日常離線測試命令：

```sh
swift test --package-path ios-app/Core
npm --prefix ios-wda test
```

兩項需要外部資料的 Swift 測試預設略過；如需重新對正式來源執行唯讀同步，可用 `LINEDRAW_LIVE_CATALOGS=1 swift test --package-path ios-app/Core --filter CatalogSourceTests.testLiveCatalogNetworkReadOnly`。該測試只讀取清單及解析短網址，不開 LINE、不送出抽選。固定快照測試只適用本次 2026/10/02 保留的兩份原始回應；快照不隨公開倉庫發布。
