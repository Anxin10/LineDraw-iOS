# iOS 1.1.0 build 16：直接開下一筆，不操作關閉鈕

## 問題證據

使用者回報「系統進度遮住關閉按鈕」。10/2 取得手機原始診斷，最近兩次批次均停在第 1 筆、完成位置 0/5，`directOpen=1`、`closeFallback=1`。其中一輪耗時 36.49 秒，頂部截圖/OCR 9 次共 6.12 秒，最後原因正是「LineDraw 系統進度仍遮住關閉按鈕」。沒有抽選點擊。

舊版雖先送下一筆網址，但要求看到完整關閉邊界或 WebView 暴露精確網址。LINE 可在相同 WebView 內替換頁面；未讀到這兩種信號時，約 0.8 秒後退回關閉優惠券流程，進而依賴被系統進度覆蓋的右上角。

## 修改

- `LocalWDA` 完全移除關閉優惠券、頂部 OCR、收合動態島、SpringBoard 滑動及等候關閉動畫的分支。點擊函式只接受抽選或加入好友目標，關閉鈕不再有特殊授權路徑。
- 每筆直接向 WDA `/url` 送出已解析網址，沿用原先的 iOS 通用連結分派。點擊成功回應、保存 SUBMITTED 後直接接下一筆，不讀取本筆中獎結果。
- 網址送出成功後才啟用新頁觀察。若 WebView 有精確網址即直接確認；若明確顯示另一個活動網址則繼續等待。沒有網址時要求同一操作/結果的至少兩次新觀察，跨過 0.2 秒穩定期間及網址回應後的 0.5 秒抵達期間。此條件不會在送出下一個網址前新增 sleep；實際畫面讀取時間也計入。
- 新頁尚未穩定時，沿用完整原生畫面讀取，避免 WebView 切換途中就使用稀疏元素查詢；必要時保留底部 OCR。畫面就緒後可沿用快速按鈕查詢，但不再從任何查詢要求關閉邊界。系統橫幅遮住頂部時，只要 LINE 的底部目標仍可辨識，就可繼續。
- 空畫面、載入中、第三方前景、對話框、多個操作目標不會滿足穩定條件；重新開頁會清除上一筆觀察。尺寸與實際目標矩形仍每次驗證，不使用跨機型固定座標。
- 網址指令失敗不視為成功；點擊回應不明仍保存 REVIEW 並停止，不重送點擊。單筆兩輪 30 秒載入仍沿用，載入失敗記 LOAD_TIMEOUT 後接續下一筆。
- 升級主 App/PairingActivity 為 build 16，Runner、配對、DDI、VPN、清單資料與使用者紀錄格式不變。

## 限制

LINE 若不提供 WebView URL，穩定畫面只能證明有可處理的介面，不能形式化證明它屬於指定活動。舊頁若在導流成功後仍長時間保持相同畫面，仍可能被視為已載入；本次依使用者要求採直接連結與畫面穩定策略，沒有宣稱消除此類身分不明風險。不同網址具有完全相同內容時不再強制關閉或要求活動名稱核對。

實機唯讀複查只開活動頁、不加入好友、不抽選、不兌換；不能用來推論未抽過活動的實際送出速度。所有私人診斷與裝置資料保存在 `.runtime`，不納入公開來源。


## 實機檢查進度

第一輪唯讀複查直接開出第一筆並辨識 COMPLETE；第二筆出現 `pause(畫面顯示對話框)`，沒有抽選點擊，不能計為五筆通過。這兩輪均未呼叫頂部 OCR、滑動或關閉。已補上唯讀模式的有界畫面摘要，進一步核對對話框種類；不把這次中斷當作已修復證據。


## 實機對照結果

- 加入診斷後確認先前的 Alert 是 LINE「無法連線」，位於畫面中央（不是系統進度）；保留對話框保護。曾比較指定 LINE bundle ID 的深連結方式，最終沿用原版通用連結分派，未保留不必要的導流方式變更。並無足夠證據將 LINE 對話框單獨歸因於網路或該選項。
- 通用連結 + 初始快速元素查詢曾在第一筆發生 `The network connection was lost`；最終版本在新頁等待階段保留原本完整畫面讀取，只在就緒後使用快速查詢，避免新增在 WebView 切換期間查詢的行為。
- 完整讀取對照：已抽過的 LINE 五筆唯讀複查 **5/5 通過**，依序 COMPLETE、ALREADY、ALREADY、COMPLETE、ALREADY，共 **74.42 秒**（含啟動及清理）。5 次 URL 指令、5 次就緒；沒有點擊、關閉、滑動、頂部 OCR。實機截圖確認 LineDraw 系統進度保持展開、蓋住頂部時仍接續至最後一筆。這是對照模式，不取代最終預設模式驗收，也不是新券抽選速度。
