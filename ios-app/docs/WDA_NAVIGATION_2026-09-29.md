# WDA 換頁失敗修正（build 11）

## 問題證據

使用者回報 build 10 只完成第一筆，後續顯示「手機端 WDA 回應不完整」。讀回本機資料確認本輪第一筆為 SUBMITTED，完成位置 1 / 5，後四筆沒有送出紀錄。舊版把非 2xx、缺少 value、過大回應等情況合併成同一句錯誤，沒有保存原始 HTTP 狀態，因此不能事後斷言該次伺服器的確切錯誤碼。

補上診斷後，實機確實重現 **GET source → HTTP 500 / unknown error / Cannot get 'xml' source of the current application**。發生於關閉 LINE 優惠券後、打開下一筆之前，舊流程為了取得換頁基準而讀取完整元素樹。重讀仍失敗，因此主要修正是移除此處對 LINE 主畫面／聊天介面 XML 的依賴。

只讀複查重現換頁卡住：WDA 的關閉點擊已回應，但優惠券仍留在畫面。診斷截圖顯示 **LineDraw 的系統工作進度即時動態展開，遮住 LINE 右上角關閉按鈕**。關閉目標的位置為實際 AX 元素，不是預設座標；然而 AX 仍可回傳被系統覆蓋的 LINE 元素，座標點擊可能落在系統進度介面。

## 修正

- 背景工作標題只在離開 App 前設定一次。執行期間不再隨每次輪詢／換頁改標題；只有總數及完成數真的改變才更新進度。App 內仍保留完整執行階段文字。實測只減少更新仍不足以使已展開的橫幅收起。
- 點頂部關閉按鈕前，使用 Vision 在截圖頂部辨識唯一的「LineDraw 抽選」標題；只在自己的進度橫幅左側向中央滑動，然後重新辨識確認已收起。接著重新取得 LINE 畫面與關閉目標，才送出關閉點擊。無法讀取截圖或橫幅仍在時停止，不點取消工作按鈕。此收起手勢符合 [Apple 的動態島操作說明](https://support.apple.com/en-ie/guide/iphone/-iph28f50d10d/ios)。
- 關閉優惠券後，用兩次新截圖辨識確認頂部優惠券標題及自身遮擋橫幅均消失，建立「舊券已關閉」的換頁邊界，直接開下一個網址；不再抓取 LINE 主畫面／聊天介面的完整 XML。等待有上限，取消後不再開頁或點擊；不重複送出關閉點擊。新優惠券仍需通過原來的兩次穩定畫面與底部按鈕確認。
- WDA 回應先解析協定錯誤，再處理 HTTP 狀態；錯誤可分辨指令、HTTP 碼與有限的錯誤類別，不把原始頁面／伺服器錯誤文字放入一般診斷。
- 只對 GET source／GET wda/activeAppInfo 的逾時或暫時性伺服器／格式失敗重讀一次。HTTP 暫時錯誤間隔 200 ms。無效 session／參數直接停止；POST 抽選點擊、開網址、建立 session 均不自動重送。
- 一般紀錄保存錯誤摘要及批次停止原因。Debug 私有檔保存最後一次有限長度的 WDA 錯誤訊息，排除於分享診斷及來源發行；未保存成功的 XML 或畫面。
- Debug `--device-review --inspect-navigation` 只開頁、關閉優惠券與觀察按鈕，不提交抽選、不變更參加紀錄。
- 系統進度保留一個實際的收尾工作單位，用於關閉 WDA 與保存最後狀態，避免最後一筆進度到 100% 後背景執行提前結束。正常批次先保存結束原因；只讀測試在 WDA 清理完畢、通知系統工作完成之前保存終態報告。

## 驗證

Core 60 項測試通過，包含讀取復原上限、POST 不重送、JSON null 點擊確認、Vision 區域座標、關閉動畫、逾時與取消。Debug 實機簽署建置及 Release 編譯通過。

最終實機只讀檢查：**5 / 5 通過，30.64 秒（含啟動／換頁／清理）**，報告終態為 `passed / finished`。順序為第一筆 `ALREADY`、後四筆 `READY_NOT_TAPPED`。只執行四次關閉優惠券、一個系統橫幅收合手勢及五次開網址；沒有抽選／加好友／兌換操作。這不是五次真正送出抽選的速度測量。

工作已執行 WDA session／server 收尾並保存 `passed`。程序檢查仍看到 Runner 宿主，因此本次另外由 Mac 結束該測試宿主，再開回沒有測試參數的一般 LineDraw；不宣稱已驗證 Runner 程序必定自行退出。前後比對：六筆參加紀錄（含使用者已送出的新第一筆）、全部清單、設定、手動撤銷及待同步資料均不變。其餘四筆保留給使用者抽選測試。
